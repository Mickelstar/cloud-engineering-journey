# Day 30 - Final Cloud Engineering Portfolio Review



## Objective



Review and consolidate the practical work completed during the 30-day cloud engineering challenge, ensuring the portfolio communicates technical experience, validation, security awareness, and operational lessons clearly.



## Journey Overview



The repository documents hands-on work across these areas:



- AWS networking, VPCs, security, and IAM.

- EC2, load balancing, and Systems Manager.

- Docker, Amazon ECR, ECS, and Fargate.

- GitHub Actions and container image automation.

- CloudWatch monitoring, logs, and alarms.

- CloudTrail event investigation.

- Python application development and testing.

- Container security and non-root execution.

- AWS resource and cost-awareness reviews.

- CloudFormation template validation and change-set inspection.

- Technical documentation and career positioning.



## Selected Technical Outcomes



### Container Deployment

Built and pushed a container image to Amazon ECR, ran an ECS Fargate task, and verified startup through CloudWatch Logs.



### IAM and Security Review

Inspected IAM users, roles, policies, and permissions, including the scope of permissions used by automation.



### Monitoring and Investigation

Reviewed CloudWatch alarms and metric availability, and used CloudTrail Event History to inspect recorded AWS management activity.



### Infrastructure as Code

Created and validated a CloudFormation template, reviewed a change set showing a proposed S3 bucket addition, and deleted the change set without executing it.



### Systems Manager

Reviewed EC2 instance profiles and SSM configuration. The inspected EC2 instances were stopped, so managed-instance connectivity was not confirmed.



### Cost Awareness

Inspected AWS resources for potential ongoing costs and avoided deleting resources without confirming their dependencies.



## Engineering Principles Practised



- Validate before deploying.

- Apply least-privilege access.

- Treat missing monitoring data as an observability gap.

- Review resource dependencies before cleanup.

- Consider cost when designing and operating cloud infrastructure.

- Record test results and limitations accurately.

- Keep technical documentation clear and reproducible.
